# Test plan: admin flows

This plan follows an admin through the users, roles and permissions pages, in a real browser against the Go server and the stub API. It covers what Go cannot see: what is listed once the server, the stub and the browser have all answered, what a save or a grant or a delete sends and shows, where focus lands after the page's own action, and the confirm before a delete. The markup, the status lines and the error responses of each handler are pinned by the Go plans (users, roles, permissions, errors) and are not repeated here. The mechanisms the pages share, such as the busy state, a second action dropped while one is in flight, and typed values put back after a swap, are in glue.md (HG).

The tests are in test/js/tests/flows-admin.spec.js, and each title starts with its row ID, so `--grep FA-31` runs one row. Every test signs in through `signIn` with the stub seed named in its precondition. The default seed has the users `alice` (role `system`), `bob` (role `bee_admin`) and one account without a username, the roles `system`, `owner` and `bee_admin` (which grants `beenamegenerator.admin` and `ratelimit` 100), and five permissions: `beenamegenerator.admin`, `ratelimit` (int), `petpictures.pets` (string_list), `motd` (string) and `datastore.admin`. `writes` is what the stub recorded for the session as method, path and body, for every call that is not a GET, and `calls` is every call. A forced failure answers once with the status and detail given, after letting `skip` calls through. A gate holds the answer to a call until the test releases it.

A confirm dialog is answered in the test: the first one dismissed and the second accepted where a row says so.
