# Test plan: site flows

This plan follows a visitor through the account page, the admin access checks and the bee name review page, in a real browser against the Go server and the stub API. It covers what Go cannot see: what the scripts and htmx do with the markup, and what a page shows once the server, the stub and the browser have all answered. The markup, the status lines and the error responses of each handler are pinned by the Go plans (account, bee, errors) and are not repeated here. Clicking Link on a platform is in scripts.md (SC-35 to SC-37). A request the browser cannot send, which shows the unreachable message, is HG-61 in glue.md.

The tests are in test/js/tests/flows-site.spec.js, and each title starts with its row ID, so `--grep FS-07` runs one row. Every test signs in through `signIn` with the stub seed named in its precondition, except the signed-out one. `writes` is what the stub recorded for the session, as method, path and body, for every call that is not a GET. A forced failure answers once with the status and detail given.

Links in the account rows use `LINKS`: a verified Discord link `someone#1234` with logins allowed, and an unverified Twitch link `streamer99` with logins not allowed.
