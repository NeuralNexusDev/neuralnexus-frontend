# Test plan: page

## page.go

| ID | Function | Scenario Type | Scenario | Precondition | Expected Result | Priority | Notes |
|----|----------|---------------|----------|---------------|------------------|----------|-------|
| PG-01 | `noStoreHandler` | Happy Path | The header is set before the next handler runs and the next handler is called | Next handler records the `Cache-Control` it sees, then writes 418 | The next handler saw `no-store`; status 418; `Cache-Control` is `no-store` | P1 | |
| PG-02 | `pageRoute` | Happy Path | A route answers with Cache-Control no-store when its handler succeeds | Handler renders one component and returns nil | Status 200 and `Cache-Control` `no-store` | P1 | The failure side is ER-17 |
| PG-03 | `pageAction` | Happy Path | An action hands its handler the form from the body and the query, and a DELETE only the query | `HX-Request: true`; POST then DELETE to `/x?from=query&both=q` with body `from_body=1&both=b` | POST: `from` `query`, `from_body` `1`, `both` `b` (body first). DELETE: `from` `query`, `both` `q` and no `from_body` | P0 | Go reads no body for a DELETE, which is why the delete routes take their grant form from the query |
| PG-04 | `pageAction` | Error Path | An action without HX-Request answers a plain 403 and no fragment | POST without `HX-Request` | Status 403; body exactly `Forbidden` and a newline; `Content-Type` `text/plain`; no `HX-Retarget` or `HX-Reswap` | P0 | A page of ours always sends the header, so there is no fragment to swap into and the answer stays plain. The handler not running is ER-20 |
| PG-05 | `requireHTMXForWrites` | Happy Path | Reads reach the route, also from another site and without HX-Request | GET, GET with `Sec-Fetch-Site` `cross-site`, HEAD and OPTIONS, none with `HX-Request`, on a mux with `GET /unlisted` and a catch-all | 204, 204, 204 and 202 (the catch-all answers OPTIONS) | P0 | Table-driven |
| PG-06 | `requireHTMXForWrites` | Error Path | A write without HX-Request true is refused with a plain 403 | POST to a listed route with no header, with `HX-Request` `false`, with it empty, with `Sec-Fetch-Site` `same-origin` and with `none`; DELETE to a listed route without the header | Status 403 and body `Forbidden` and a newline in each case | P0 | Table-driven. The answer stays plain for the reason in PG-04 |
| PG-07 | `requireHTMXForWrites` | Error Path | A write from another site is refused even with HX-Request | POST with `HX-Request` `true` and `Sec-Fetch-Site` `cross-site`, then `same-site` | Status 403 both times | P0 | |
| PG-08 | `requireHTMXForWrites` | Happy Path | A write with HX-Request from the same origin or the address bar reaches the route | POST with `HX-Request` `true` and no `Sec-Fetch-Site`, then `same-origin`, then `none` | Status 204 from the route each time | P0 | |
| PG-09 | `requireHTMXForWrites` | Edge Case | A route that falls to the catch-all is not checked | POST to `/anywhere` and DELETE to `/unlisted` (listed for GET and POST only), both without `HX-Request` | Status 202 from the catch-all both times | P1 | The catch-all is the `/` pattern |
| PG-10 | `requireHTMXForWrites` | Edge Case | A write to a path whose route does not list the method keeps the mux answer | A mux with only `GET /only`; POST to `/only` without `HX-Request` | Status 405 | P1 | The route table has no catch-all for these paths |
| PG-11 | `shell` | Happy Path | A shell renders its page with no-store and calls no API | `shell(components.AdminDashboardPage())` served with a fake API attached | Status 200; body holds `hx-get="/admin/cards"`; `Cache-Control` `no-store`; the API saw zero calls | P0 | The page loads its own content, so a signed-out visitor gets the shell and then a redirect from the fragment |
| PG-12 | `shellFor` | Happy Path | shellFor passes the decoded id from the path to the page and sets no-store | `GET /x/{id}` with `/x/a%2Fb%3Fc`; the page function records its argument | The id is `a/b?c`; `Cache-Control` is `no-store` | P0 | |
| PG-13 | `shellFor` | Edge Case | A hostile id reaches the page escaped | `GET /admin/users/{id}` with the id `<img src=x onerror="window.__xss=1">id` path-escaped, through `shellFor(components.AdminUserPage)` | Body has no `<img src=x`; the `hx-get` is `/admin/users/%3Cimg%20src=x%20onerror=%22window.__xss=1%22%3Eid/editor` | P0 | |
| PG-14 | `shell` | Error Path | A page that fails to render gets a plain 500 and no fragment headers | `shell` of a component that returns an error | Status 500; no `HX-Retarget` and no `HX-Reswap` | P2 | A shell is a whole page. There is no fragment to put the failure in, so it goes to the connection as a plain error |
| PG-15 | `render` | Happy Path | render writes the parts in order | Three components writing `a`, `b` and `c` | Body is `abc` | P1 | |
| PG-16 | `render` | Error Path | render stops at the first part that fails | Components writing `a`, failing, and writing `c` | Body is `a` | P1 | |
| PG-17 | `renderAll` | Happy Path | renderAll sets the content type and ends with the cleared banner | Two components | `Content-Type` `text/html; charset=utf-8`; the body is both parts and then `<div id="page-error" hx-swap-oob="innerHTML"></div>` | P0 | Every successful fragment empties the error banner this way, see CU-41 |
| PG-18 | `renderAll` | Edge Case | renderAll writes only the parts it is given | One component | Body has no `<html`, `<body` or `<head` | P1 | The page routes answer fragments, never documents |
| PG-19 | `redirectHTMX` | Happy Path | redirectHTMX sets HX-Redirect with an empty 200 | `redirectHTMX(rec, "/admin/roles/7")` | Status 200; `HX-Redirect` `/admin/roles/7`; empty body | P1 | |
| PG-20 | `nothingToSave` | Happy Path | nothingToSave tells the status line, keeps the page and clears the banner | `nothingToSave(rec, r, "admin-user-status")` | Status 200; `HX-Reswap` `none`; body holds `<p id="admin-user-status" hx-swap-oob="innerHTML">Nothing to save</p>` and the `page-error` clearing element | P1 | |
| PG-21 | `hasPermission` | Happy Path | A held node matches whole or with a value after a colon | Held `["ratelimit:1000","users.admin","roles.admin:1"]`; nodes `users.admin`, `roles.admin` and `ratelimit` | True for each | P0 | |
| PG-22 | `hasPermission` | Edge Case | A node that only resembles a held one does not match | Held `["users.administrator","xroles.admin","roles.adminx:1","Users.Admin","beenamegenerator\|*"]`; nodes `users.admin`, `roles.admin`, `beenamegenerator.admin` and `beenamegenerator` | False for each | P0 | The match is a whole node or the node followed by a colon, and is case-sensitive |
| PG-23 | `hasPermission` | Edge Case | No permissions or no node match nothing | A nil list and an empty list with `users.admin`; the list `["users.admin"]` with an empty node | False in each case | P1 | |
| PG-24 | `secondary` | Happy Path | No error gives no message and no error | `secondary(nil)` | Empty message, nil error | P1 | |
| PG-25 | `secondary` | Happy Path | An API error gives its message and no error | `apiError{Status: 500, Message: "database down"}`, then a 403 `Forbidden` wrapped with `%w` | `database down` and nil, then `Forbidden` and nil | P0 | The page shows the message in place and carries on |
| PG-26 | `secondary` | Edge Case | An error that is not an API error gives the generic message | `errors.New("boom")` | `Something went wrong` and nil | P1 | |
| PG-27 | `secondary` | Error Path | A 401 is returned as the error with no message | `errUnauthorized` wrapped with `%w` | Empty message and the same error | P0 | A part of the page cannot fail on its own when the session is gone |
| PG-28 | `permissionLink` | Happy Path | A held node shows the link after one permissions call that carries the session | Permissions `["ratelimit:5","beenamegenerator.admin:1"]`, node `beenamegenerator.admin`, session cookie `jwt-value` | Status 200; body is the link; the API saw only `GET /users/me/permissions` with `Cookie` `session=jwt-value` | P0 | |
| PG-29 | `permissionLink` | Happy Path | Any one of several nodes is enough | Permissions `["roles.admin"]`, nodes `users.admin` and `roles.admin` | Body is the link | P1 | |
| PG-30 | `permissionLink` | Edge Case | Without a held node the answer is an empty 200 | Permissions `[]`, `["users.admin","roles.admin"]`, `["beenamegenerator\|*"]`, `["beenamegenerator.administrator"]` and `["xbeenamegenerator.admin"]`, node `beenamegenerator.admin` | Status 200 and empty body each time | P0 | Table-driven |
| PG-31 | `permissionLink` | Error Path | A failed permissions call is an empty 200 and not a failure response | The permissions call answers 500, 403 and 401 | Status 200, empty body, no `HX-Redirect` and no `HX-Retarget` in each case | P0 | The bee name generator page is public and loads this link by htmx, so redirecting a 401 would send every signed-out visitor to the login page. | PG-32 | `rowGone` | Happy Path | A numeric id gives the directive that deletes the prefixed row | `rowGone("admin-permission-", "3541025163146757800")` | One part that renders `<div hx-swap-oob="delete:#admin-permission-3541025163146757800"></div>` | P0 | |
